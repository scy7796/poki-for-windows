# Poki 手机独立运行

使用 [全链路操作文档](references/operations.md) 配置一台指定的测试手机。
先读文档第 1、2 节，再按实际连接方式执行后续步骤。遇到签名或配对故障时查第 8 节。

## 执行流程

1. **固定版本和对象。** 核对自己的工作树、分支、未提交修改和实际安装版本。确认目标手机以及当前是否有人使用它。多人共用一台手机时，先约定谁在使用，同一时间只有一个人或一个代理操作它；等待人工操作时让出手机。完成标准是能将每份证据对应到一台手机和一个提交。
2. **选择本机连接。** 用户需要保留现有 VPN 时，优先检查其是否支持本机回环，并在 Poki 选择 External app。没有兼容外部连接时，使用具备相应签名能力的内置版本，由用户完成系统 VPN 验证。以开发服务连接检查通过为准。完成标准是连接检查通过，且网页仍能按原有网络设置加载。
3. **准备应用和配对。** 按文档第 3、4 节安装 Poki，检查嵌套可执行文件签名，启用开发者模式和 UI 自动化，在手机上完成配对。默认只装 Poki 一个应用；任务指定旧的 Runner 路径时，另装同一签名体系的 Poki Runner。密码和配对码由用户在手机上输入。完成标准是配对完成、权限齐备，且 Poki 日志出现 `in-process session ready`；Runner 路径的完成标准是 Runner 能由 Poki 启动。
4. **接通自建中转。** 在用户授权的账户中部署独立中转，将地址填入 Poki，创建该客户端专用的连接。连接器网址只进入客户端的私有配置表单。完成标准是中转就绪，真实 MCP 客户端能发现工具并收到手机回复。
5. **接入 Codex 手机端。** 按文档第 6 节添加个人 MCP 插件，在手机 Codex 中选择云端主机并选中插件。插件卡片存在或账号已连接不等于操作成功。完成标准是云端任务实际调用该插件，目标手机产生对应结果。
6. **验证并交回。** 先确认已拔掉 USB，再从手机发起一项新任务。分别记录基本操作、审批和稳定性结果。交回实际测试提交、网络类型、耗时和脱敏证据；合并和发布按任务授权执行。

## 证据和隐私

- 对外文档使用“内置本机连接”“现有 VPN”“自建中转”等中性称呼，以及示例标识符。
- 实际服务地址、连接器网址、访问令牌、配对记录、账户资料和设备标识只保留在必要的本地私有配置中。日志和截图先检查再分享；连接配置页避免录入演示素材。
- `10.7.0.1` 是本方案固定的手机内部回环地址，供配置使用，不代表用户的服务器或网络出口。
- 协议 `tools/list`、客户端实际可用工具、手机操作结果分别核对。一次成功打开应用，只证明当次基本操作成功。
- 记录未执行的条目为“未测”。锁屏恢复、蜂窝网络、长时间后台和灵动岛审批分别验收。用户已明确要求交回时，保留剩余项，由用户决定后续安排。

## 已有事实的使用

文档第 9 节保存 2026-11-07 的验证边界。它可以帮助复现配置，但不能替代新版本的设备验收。
更新安装版本、签名、连接方式或运行条件后，只补查受影响的行为。保留已有有效证据，不为文档整理重新操作用户手机。
