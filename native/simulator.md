# Simulator and platform adapter

`src/platform.mjs` exposes `platformTool(devices, name, arguments)` and returns JSON values. Its context supplies `target()` and the selected-device/frame fields. `src/simulator.mjs` exposes `simulatorRequest(udid, request)` with screen coordinates in points.

The simulator executable reads one JSON request on stdin, except for input, which has its own session mode described below. It selects the active Xcode from `DEVELOPER_DIR` or `xcode-select -p` and connects directly to CoreSimulator services. It does not click macOS screen coordinates.

Simulator accessibility uses CoreSimulator and AccessibilityPlatformTranslation to inspect actual objects and their properties.

Before a shutdown simulator boots, its accessibility preferences are prepared while preserving other keys. Startup checks a real accessibility response. A fresh SpringBoard may return no application from the window-server foreground query even with accessibility enabled; the bridge then performs an actual screen accessibility hit test and resolves that object's process to its application translation. A page with nothing at the screen's centre answers that hit test with an error, so the bridge also tries further up and down the same vertical line before reporting no foreground application. It does not infer the foreground from launch history. This path was verified on the same fresh simulator that originally failed.

```sh
xcrun clang -fobjc-arc -fblocks \
  -framework Foundation -framework AppKit -framework UniformTypeIdentifiers \
  native/simulator.m -o build/simulator
```

The HID transport is `com.apple.coredevice.feature.remote.hid.digitizer`, with Indigo digitizer, keyboard and consumer-button envelopes. Rotation uses `PurpleWorkspacePort`. Accessibility uses archived `AXPTranslatorRequest` messages over `com.apple.CoreSimulator.accessibility`. A missing bundle identifier during app startup is resolved from the accessibility PID, the actual process executable path, and the simulator's installed application paths. Clipboard reads use an isolated `SimPasteboardPlus` pasteboard snapshot and classify image types with UniformTypeIdentifiers.

Each new connection to the HID service makes the simulator's `dtuhidd` create six virtual input devices in `backboardd`, and closing the connection removes them. The service answers the first message before those devices are up, so a reply proves nothing about delivery. A tap sent over a connection that closes before they are up is lost with no error. Setup takes longer the more connections the simulator has served: after several hundred connections, a tap landed 1 time in 12 when the connection stayed open 300 ms, 9 in 12 at 500 ms and 12 in 12 at 700 ms; after a reboot it landed every time. The connections alone do this: on a rebooted simulator a tap over a 300 ms connection landed 40 times in 40, and after 600 more connections that sent no touches it landed 13 times in 20. A connection per tap therefore degrades the simulator it is driving. `src/simulator-input.mjs` runs one `build/simulator --hid-session <udid>` per simulator instead. It holds one connection, takes one JSON line per batch of events and answers with one line. It waits 800 ms after connecting before sending, and `launch_app` opens it ahead of the launch so that wait overlaps the launch. The session closes after 30 idle seconds or when the service exits. Exit status 75 means the connection was gone before anything from the request was sent, which is the one case that gets a second attempt, on a new connection.

The protocol implementation references Meta idb; its MIT license is preserved in `LICENSE.idb`. See [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) for the pinned source files and open-source notices.

ASCII typing uses HID, after `simctl keyboard <id> en_US` selects a keyboard no input method can rewrite. A simulator created on a Chinese Mac otherwise types through Pinyin. Selecting `en_US` right after a freshly launched app's first focus can be lost: all 13 tries typed through Pinyin when the input connection had opened on Pinyin, and 2 of 5 when it had opened on `en_US`. Selecting it before the launch held 24 of 24 times, and on a field that has had focus for a while the selection takes effect at once. So the selection runs before `launch_app`, before each new input connection and again before typing. If a cleared field still differs on readback, the pasteboard path used for Unicode takes over; on the tested iOS 27.0 runtime that path leaves the field empty, because the simulator pasteboard stays empty. An iOS paste-permission prompt produces an error with `reason: "system_prompt"` and the prompt's text; the adapter does not answer it, and does not submit while it is pending, so answer it with `handle_alert`. The requested text remains on the device clipboard so a later human approval pastes the intended value.

Emoji keyboard detection is a local compatibility enhancement. This runtime exposes emoji keys as generic accessibility buttons, so `hide_keyboard` also recognizes a grid of distinct emoji identifiers together with the `delete` key and a dictation or keyboard-switch control. A normal button merely labeled Delete is insufficient. On the tested iOS 27 simulator, consumer HID `0x0c/0xb8` with an 80 ms hold leaves the emoji panel visible. The tool now reports that failure truthfully and preserves the field text instead of returning `already_hidden`. It does not switch input methods or send Escape as a workaround. Use a keyboard hide control, or tap outside the field in an app that supports dismissing it that way. When no keyboard is visible, the tool sends no toggle.

Keyboard input is sent serially in batches of complete keystrokes, each bounded by 30 seconds of scheduled delays and 5,000 events. A batch ends with all keys and modifiers released. The helper timeout is its scheduled duration plus 15 seconds for connection and delivery. This allows long ASCII input and the public 200-key repeat limit without a fixed one-minute cutoff. Text is still checked only after all batches finish; a failed batch stops the action and never submits it.

Gesture input stays in one helper process, and one batch holds at most 10,000 events. Up to 2,000 motion samples keep a 60-second swipe or drag below that limit. `draw_strokes` sends each stroke as its own batch, because the helper lifts a touch still down when a batch ends: its 8,192 points become one event each, delayed by the gap to the previous point, which may be a fractional number of milliseconds, and strokes after the first wait 80 milliseconds before touching down. The helper sleeps for each gap after sending the previous event, so a stroke runs somewhat longer than its last `time_ms`; long presses accept the public 60-second maximum, and drag holds plus motion can total 70 seconds. The helper validates all delays before sending any input. On an input error or timeout signal it sends releases for held keys, buttons and touches before closing the connection.

Clearing before paste checks the actual accessibility selection range. If an active IME consumes Select All, Escape cancels its marked composition before selection and deletion are retried. The field must remain focused and read back empty before any paste is sent. This avoids appending new text to an unfinished composition.

Physical recording retains one ffmpeg encoder while `resumeRecordings(context, target)` reconnects the display-stream receiver after input. Simulator recording uses `simctl io recordVideo`. Both finalize and inspect an actual H.264 movie before returning success from `stop_recording`.

`build_and_run` requests dSYM generation and records its actual Mach-O UUIDs. `get_crash` invokes `atos` only when a crash image has the same UUID and architecture; unmatched frames retain their original report symbols. Symbolication state is scoped to the current server session.

The disposable fixture is in `bin/fixture-app`. Its bundle identifier is `local.pokimcp.fixture`; it exposes a text field, counter, gestures, slider, alert, navigation, scrolling, zoom, an intentional crash and a small Documents state file. Acceptance must check resulting UI state, file contents or video frames; a sent HID event alone is not proof of interaction success.

Device APIs retain real platform limits. Simulator Reduce Motion and Reduce Transparency require Settings. The tested physical device supports Increase Contrast readback, while its `getlargeraccessibilitysizesenabled` action reports CoreDevice ActionError 2, not implemented. The setter uses a top-level `{enabled: boolean}` input; errors are propagated rather than reporting a successful setting change.
